Handle a missing cell with match

Handle Some and None explicitly so an invalid brush coordinate becomes a safe no-op.

Previously: Turn coordinates into safe indices. Keep that working result available before starting this lesson.

Why we need this now

Our index helper now tells the truth: some positions do not name a stored cell. That result is only useful if the caller respects it. Matching Option turns a potential panic into an explicit choice at the boundary between user input and world mutation.

Your result: Handle Some and None explicitly so an invalid brush coordinate becomes a safe no-op.

01A possible index is not an index yet

Option has two alternatives: Some carries a valid usize, while None carries no index. You cannot use the Option itself to index a vector because it is not a guarantee of a position. The caller must inspect the alternative and decide what absence means for its operation.

For painting just outside the view, doing nothing is reasonable. For a fixture that claims a known-valid position, absence may indicate a broken test setup and should fail loudly. The same type can support different policies; what matters is that the policy is visible rather than hidden in an arbitrary fallback number.

02Match binds the carried value

In match index(...) { Some(i) => ..., None => ... }, the Some arm introduces i for the carried index. That binding exists only in the arm where the value is present. The None arm cannot refer to a nonexistent index.

Use the successful arm to mutate one slot and the missing arm to return false. The bool result lets the caller report whether a paint command affected the stored rectangle. This is already a useful interface for tests and later input feedback. It avoids giving every caller direct access to unchecked vector indexing.

03Why index zero is not a fallback

Index0 is the top-left valid slot. Converting None into0 would turn an out-of-bounds brush stroke into a real edit at the world origin. That failure might appear as mysterious sand or erasure in the corner, far from the cursor. A numeric sentinel is safe only if the domain excludes it and every caller obeys the convention; our vector domain does not exclude0.

Likewise, unwrap on an ordinary edge click turns an expected condition into a panic. unwrap can be reasonable in a tightly controlled test whose setup guarantees Some, but it is not a substitute for defining runtime input behavior.

04Exercise both branches, not only the happy path

Use a tiny vector with a distinctive first value. Paint a valid coordinate, then try a negative coordinate and a coordinate exactly at width. Assert the invalid attempts return false and the first value is unchanged. This directly protects against the index-zero fallback bug.

Later, Option will recur in map lookups, neighbour searches and collision queries. The transferable idea is to distinguish “there is a value” from “there may be a value,” then choose the missing-case behavior according to the operation’s contract.

Download this worked example ↧

fn index(x:i32,y:i32,w:i32,h:i32)->Option<usize> {
    if x<0 || y<0 || x>=w || y>=h { None }
    else { Some(y as usize*w as usize+x as usize) }
}
fn paint(cells:&mut [u8],x:i32,y:i32,w:i32,h:i32,value:u8)->bool {
    match index(x,y,w,h) {
        Some(i) => { cells[i]=value; true }
        None => false,
    }
}
fn main() {
    let mut cells=vec![0;8];
    assert!(paint(&mut cells,2,1,4,2,7));
    assert!(!paint(&mut cells,-1,0,4,2,9));
    assert_eq!(cells[0],0);
    assert_eq!(cells[6],7);
    println!("edge paint is a no-op");
}

Read what each part does

  1. The slice is borrowed mutably so the caller keeps ownership of storage.
  2. The example uses u8 values to isolate Option handling; production uses Material.
  3. The missing branch performs no mutation.

Expected result

edge paint is a no-op. The helper assumes a validated4×2 allocation; production World should enforce that invariant.

Return the previous value

Change the painting interface to return Option<u8> for the replaced value.

Need a hint?

The successful arm can carry information back.

Worked solution

match index(x,y,w,h) {
    Some(i) => { let old=cells[i]; cells[i]=value; Some(old) }
    None => None,
}

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Cannot index with Option<usize>

What is happening: The presence case has not been unpacked.

Try this: Match Some(i) before using i as an index.

A click outside changes cell0

What is happening: None was replaced by a valid fallback index.

Try this: Represent absence explicitly and return without editing.

Ordinary edge clicks panic

What is happening: unwrap was used for expected missing coordinates.

Try this: Handle None as the chosen no-op or feedback case.

Explain it without the example

Why should an invalid coordinate not default to index zero?

Reasoning to compare

It would turn an out-of-bounds edit into an unintended change to the first cell. None preserves the distinction between missing and valid.
