Bound accelerated slow processes

A cell cannot rot through two stages in one tick. Probability 0 stays 0 and probability 1 stays 1, including fallback mode.

Previously: Sample slow work deterministically. Keep that working result available before starting this lesson.

Why we need this now

Accelerated seasons should not reduce every cell to one huge irreversible jump. The revised design first increases the number of unit slow-work visits, then uses a capped approximation only when necessary. We need to preserve probability bounds and intermediate states while admitting where equivalence ends.

Your result: A cell cannot rot through two stages in one tick. Probability 0 stays 0 and probability 1 stays 1, including fallback mode.

01Spend more picks before increasing step size

For multiplier M, choose P=min(16*M,256). For M up to 16, each pick is an ordinary unit opportunity and the expected visit rate per world day remains aligned with normal mode, assuming the source distribution is appropriate. Above the cap, m=16*M/P describes represented unit opportunities per selected cell. The number of index attempts is bounded by overlapping chunks, not merely visible area; at the 720p active size chunk alignment can reach 35 overlapping chunks.

02Scale a chance through survival probability

If one independent opportunity succeeds with probability p, surviving m opportunities without success is (1-p)^m. Therefore at least one success has chance 1-(1-p)^m. For integer m this is the familiar repeated-trial result; for fractional m the design uses its continuous survival extension. It stays within [0,1] for valid inputs, including exactly one when p=1. It does not represent the number of multiple possible events; the rule must define at most one event per allowed slow update.

03Preserve small rates and stage boundaries

The spec floors m*rate before adding progress. If a small fractional rate is repeatedly rounded to zero, growth can stop forever. Choose fixed-point progress, a retained fractional remainder, or a documented stochastic rounding policy. Clamp the addition to the remaining distance to the next stage, not to a total cap added on top of already accumulated progress. When Wood reaches RottenWood, do not process the new stage again in the same simulation tick. Distinct picks plus staged edits/full tick stamps enforce that across neighbour creation too.

04Test the approximation, not a false equivalence

At high m, spatial chains and multi-stage decay take at most one step per cell per executed tick. A tree cannot add its whole future canopy in one visit merely because many days were represented. That is a deliberate approximation and may produce different shapes at the same date under different hardware caps. Run fixed-seed and multi-seed fixtures at 1x,16x,64x including forced M=32; check acceptance outcomes and intermediate visibility, not exact world identity across unlike multiplier sequences.

Download this worked example ↧

fn effective_probability(p:f64,m:f64)->f64 {
    assert!((0.0..=1.0).contains(&p) && m>=1.0);
    1.0-(1.0-p).powf(m)
}
fn stage_progress(current:u16, increment:u16, cap:u16)->u16 {
    current.saturating_add(increment).min(cap)
}
#[test]
fn scaled_updates_keep_bounds() {
    assert_eq!(effective_probability(0.0,32.0),0.0);
    assert_eq!(effective_probability(1.0,32.0),1.0);
    assert!((effective_probability(0.5,2.0)-0.75).abs()<1e-12);
    assert_eq!(stage_progress(240,40,255),255);
}

Exercises you actually do

Write a prediction or make an attempt before opening a solution. Use the hint if stuck; then compare reasoning and verify with the stated check. A different implementation is fine when it satisfies the same contract.

01

Calculate pick cost

What are P and m for M=8 and M=32?

Need a hint?

Use the cap before dividing represented work by picks.

Worked solution

M=8 gives P=128,m=1. M=32 gives P=256,m=2. The latter is the bounded fallback approximation.

How to verify your result

Both cases are asserted in a helper test.

02

Retain a small rate

A unit rate is 0.2 progress and the integer implementation floors each visit. What breaks?

Need a hint?

Each independent floor loses the fraction.

Worked solution

Every visit adds zero. Store progress in fifths or another fixed-point scale so five visits produce one whole unit, or retain a remainder with a documented policy.

How to verify your result

Five eligible unit visits advance progress rather than freezing it.

03

Stop a chain

A tree grows a neighbouring cell that appears later in the same pick sequence. What prevents immediate growth of that new cell?

Need a hint?

Uniqueness of source picks alone does not cover targets.

Worked solution

Defer target creation until the pass ends or mark it with a true current-tick stamp so it is ineligible again during this tick. A stale one-bit marker is insufficient for sparse old state.

How to verify your result

A two-cell chain cannot advance twice in one executed tick.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Rare processes never advance

What is happening: Fractional rates are floored to zero each visit.

Try this: Use a fixed-point accumulator or approved rounding scheme.

Wood becomes soil in one tick

What is happening: New states are processed again through repeated/target visits.

Try this: Use correct tick identity or deferred edits.

High-speed tests demand identical worlds

What is happening: Different physics/multiplier schedules are being treated as equivalent.

Try this: Check declared acceptance outcomes and record the approximation.

Explain it without the example

Why is clamping progress on each visit insufficient if picks can repeat?

Reasoning to compare

A second visit could process the newly transitioned material in the same tick. The once-per-tick rule or deferred edits must prevent that chain.
