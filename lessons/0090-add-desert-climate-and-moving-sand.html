Add desert climate and moving sand

Generate a stable desert fixture and move only eligible surface sand with a bounded, count-preserving wind rule.

Previously: Finish the 60-second vertical slice. Keep that working result available before starting this lesson.

M6 starts here. Review this milestone’s implementation plan against the current spec. The lessons teach the work; they do not silently approve new game behavior.

Why we need this now

A desert is useful when it changes the same system’s conditions, not when it introduces an unrelated second sand engine. Climate, terrain and surface eligibility should explain the new behavior.

Your result: Generate a stable desert fixture and move only eligible surface sand with a bounded, count-preserving wind rule.

01Separate biome context from material identity

A sand cell remains sand in every biome. Its material properties still govern density and wet cohesion. The desert supplies a warmer, drier ambient context, sparse vegetation and a weather policy that suppresses ordinary rain. Keep these as biome/environment inputs rather than a special movement implementation hidden behind the name DesertSand.

Start with a handcrafted dune at its resting slope. Run a no-wind control for 600 ticks. If the dune slides everywhere, the generator or repose rule is wrong before wind enters the experiment. A calm baseline is necessary to attribute later movement to the wind.

02Define what the wind may entrain

The design says wind moves sand, but that phrase alone does not choose which grains or how far. Propose an initial bounded rule: only dry surface grains with air above and sufficient wind are eligible; attempt one adjacent downwind destination using the normal movement/edit path. Whether grains lift into particles, skim the surface or first require a slope is an explicit v2 decision.

Restricting eligibility keeps buried sand from teleporting through an entire dune. Store no independent desert velocity field until it answers an actual requirement. If the chosen rule uses random probability, seed the decision from the existing tick/coordinate scheme, and test both a calm control and reversed wind using identical terrain.

03Preserve matter and the once-per-tick rule

A grain crossing into air transfers occupancy and clears its source. Scanning with the wind can otherwise encounter the same grain again and carry it across the whole row in one tick. The sample uses a moved marker attached to the destination to demonstrate the once-per-tick contract. It is a one-row eligibility experiment, not the complete 2D sand physics.

In the real world combine gravity, diagonal movement and wind in one documented priority order. A grain must not receive a full gravity move and a second independent wind update if that exceeds the accepted displacement bound. The phase safety proof must cover the combined read/write reach, including any destination check.

04Test climate and appearance together

At a desert/plain border, interpolate the weather baseline as specified, then apply the chosen no-rain desert policy explicitly. Decide whether the border has a short transition or a hard biome override; do not call an abrupt jump smooth. Water poured by the player still follows water rules even where natural rain is absent.

Use the approved midday gradient and flat/ramped sand palette. Moving grains are visible because occupied cells change, not because random sand-colour speckle is added. Review the dune silhouette over many cycles: a readable breeze should not flatten every dune in one minute. Measure mean displacement and count conservation separately from beauty.

Walk through the working example

Complete surface-transport experiment: examples/lesson_090.rs; run cargo run --example lesson_090.

Download this worked example ↧

#[derive(Clone, Copy, Debug, PartialEq, Eq)]
enum Kind { Air, Sand, Stone }
fn wind_right(row: &mut [Kind]) {
    let mut moved = vec![false; row.len()];
    for x in 0..row.len().saturating_sub(1) {
        if !moved[x] && row[x] == Kind::Sand && row[x+1] == Kind::Air {
            row.swap(x, x+1);
            moved[x+1] = true;
        }
    }
}
fn main() {
    let mut row = [Kind::Sand, Kind::Air, Kind::Air, Kind::Stone];
    wind_right(&mut row);
    assert_eq!(row, [Kind::Air, Kind::Sand, Kind::Air, Kind::Stone]);
    assert_eq!(row.iter().filter(|k| **k == Kind::Sand).count(), 1);
    println!("one tick: one eligible grain, one bounded move");
}

Read what each part does

  1. The input row represents already eligible exposed cells; production must calculate dryness/exposure in 2D.
  2. The local moved array illustrates the invariant. Reuse the world’s per-tick marking scheme instead of allocating a fresh full-world array in every rule.
  3. Stone remains an obstruction even though the wind wants the grain farther right.

Expected result

one tick: one eligible grain, one bounded move

01

Expose the scan-order bug

Remove the moved guard and run a row beginning Sand,Air,Air,Air.

Need a hint?

The loop visits increasing positions.

Worked solution

The same grain keeps becoming the next source and may reach the far end in one tick. Restore the marker or a correctly designed staged update; assert a maximum one-cell horizontal move for this fixture.

How to verify your result

The broken version fails a displacement assertion even though count remains one.

02

Keep wet sand still

Extend eligibility with a moisture argument and choose a dry threshold.

Need a hint?

Document the threshold as tuning.

Worked solution

Before the swap, require moisture below the approved threshold. Test two identical rows differing only in moisture; only the dry case moves. Do not replace a wet grain with a separate hidden material.

How to verify your result

The wet control remains unchanged.

03

Pour water in the desert

Test whether the biome override should delete player-painted water.

Need a hint?

Natural precipitation is not all water.

Worked solution

It should not. Suppressing natural rainfall does not license deleting pools or changing density rules. Evaporation may act according to ambient conditions at its documented rate.

How to verify your result

Water is conserved by movement and only leaves through an explicit sink.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Whole dunes drift instantly

What is happening: Buried grains are eligible or one grain moves repeatedly.

Try this: Check exposure and per-tick moved state.

Water vanishes on entering desert

What is happening: A biome override rewrites material instead of climate.

Try this: Apply climate to conditions, not blanket occupancy replacement.

Wind moves sand through stone

What is happening: Destination selection ignores occupancy or path.

Try this: Use the existing checked movement contract.

Explain it without the example

Why shouldn't desert sand get an entirely unrelated movement engine?

Reasoning to compare

The same material should follow consistent rules. Biome context can change conditions without duplicating fundamental mechanics.
