Make material states readable without texture noise

Build an actual-scale material contact sheet where required states remain distinguishable in day and night scenes.

Previously: Compose sky sun moon and night. Keep that working result available before starting this lesson.

Design choice to settle. The current specification leaves a decision here. The example makes the mechanism concrete; document the chosen behavior before treating it as the final game rule.

Why we need this now

The game asks viewers to notice why something burns, freezes, rots or dries. If those states look the same, the simulation can be internally correct while its cause-and-effect story is invisible.

Your result: Build an actual-scale material contact sheet where required states remain distinguishable in day and night scenes.

01Treat colour as an interface to state

A material ID supplies a base colour, while moisture, temperature, burning progress and variants may select approved changes. Use one coherent lookup rather than sprinkling colour arithmetic through simulation rules. Rendering reads state; changing a pixel colour must not change whether the material is wet.

Begin with the 21 launch material anchors from the current design. Then identify required distinctions: water versus ice, oil versus water, stone versus basalt, wood versus rotten wood, metal versus rust and smoke versus steam. A proposed palette is not approved simply because a function can return it.

02Compare pairs at the size players see

Large swatches hide tiny-cell readability failures. Make two displays: enlarged labelled swatches for discussing colour choices, and four-physical-pixel cells in a realistic terrain context. Inspect them under day, dusk, night and rain conditions.

Do not use random per-cell speckle as a shortcut. The art direction calls for flat materials or coherent ramps/variants. A wet-to-dry soil patch should lighten in an organized way that reveals change, while neighbouring unchanged soil provides a control. Avoid decorative texture that masks the actual state signal.

03Separate state appearance from event evidence

A static rust-coloured patch shows one state, but the required reaction also needs a visible transition within its deadline. Capture before and after with identical camera and lighting. For fire/lava and flashes, propose explicit brightness/saturation exceptions and check them against the no-bloom/no-reflection rules.

The contact sheet is not a substitute for reaction clips. It is a diagnostic that can tell us whether the reaction would remain unreadable even if the physics completed instantly. Add labels outside the game frame rather than adding permanent debug text to the release HUD.

04Make approval and accessibility concrete

Ask reviewers to identify the material/state without looking at its label. Record confusion pairs and revise only those until the complete scene remains calm and legible. Also inspect a grayscale or reduced-colour view as a supplementary diagnostic; it does not prove accessibility but can reveal reliance on barely distinguishable hue.

The helper below demonstrates deterministic wetness interpolation from a base dry to base wet colour. It clamps moisture to the supported range. The exact RGB choices are teaching values; the final scene-dependent keys must be approved, and temperature indicators must not accidentally introduce forbidden glow.

fn soil_colour(moisture:u8)->[u8;3] {
    let dry=[121_i32,100,81]; let wet=[76_i32,69,59];
    let m=i32::from(moisture.min(100));
    std::array::from_fn(|i| (dry[i]+(wet[i]-dry[i])*m/100) as u8)
}
fn main() {
    assert_eq!(soil_colour(0),[121,100,81]);
    assert_eq!(soil_colour(100),[76,69,59]);
    for m in [0,25,50,75,100] {println!("moisture {m}: {:?}",soil_colour(m));}
    assert_eq!(soil_colour(200),soil_colour(100));
}

Read what each part does

  1. The simulation stores moisture; this function only selects a display colour from it.
  2. Clamping prevents an invalid renderer input from extrapolating beyond the chosen wet endpoint.
  3. Use the contact sheet to decide whether intermediate keys actually communicate change at gameplay scale.

Expected result

Five progressively darker soil colours for increasing moisture, with dry/wet endpoints exactly as asserted.

01

Separate rendering from physics

Change the wet-soil colour to blue for a diagnostic. Should ignition behavior change?

Need a hint?

Follow which state the fire rule reads.

Worked solution

No. Fire reads material/moisture/temperature state, not the renderer’s RGB result. If behaviour changes, a simulation rule is incorrectly coupled to appearance.

How to verify your result

The same physics fixture hash is produced with both display palettes.

02

Find a confusion pair

At native cell size water and ice become indistinguishable at night. What should be compared first?

Need a hint?

Keep camera and lighting fixed while changing one variable.

Worked solution

Build labelled and unlabelled paired samples, compare approved colour/value variants, and retest the freeze transition in context. Do not add sparkles or bloom merely to force distinction.

How to verify your result

A reviewer identifies the pair and sees the transition without a label.

03

Record a state transition

Prepare proof that drying is visible rather than merely a counter changing.

Need a hint?

Use an unchanged control patch.

Worked solution

Capture wet-to-dry soil under fixed lighting and alongside a constant-moisture control. Record the state values and the visible colour change within the specified world-time deadline.

How to verify your result

Both the counter and on-screen difference are documented.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Every material looks like grey noise

What is happening: Independent per-cell variation overwhelms identity.

Try this: Use coherent state-driven colours and remove speckle.

Palette works only when enlarged

What is happening: Swatch review ignored four-pixel gameplay cells.

Try this: Include native-scale, scene-context comparisons.

Drying disappears at sunset

What is happening: Lighting changes mask the material transition.

Try this: Test with fixed lighting first, then approve the state signal under time-of-day variation.

Explain it without the example

Why does a beautiful enlarged colour swatch not establish gameplay readability?

Reasoning to compare

Players see tiny cells under changing lighting and weather. Identity must survive the actual scale and surrounding materials.
