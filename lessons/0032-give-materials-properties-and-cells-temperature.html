Give materials properties and cells temperature

Separate shared material properties from per-cell state and measure the actual proposed cell layout.

Why we need this now

Two sand cells have the same material conductivity but can have different temperatures and moisture. Mixing those concepts wastes storage and obscures rules. We will put stable properties in a lookup and changing state in each cell, then check the real size rather than trusting a field-size sum.

Your result: Separate shared material properties from per-cell state and measure the actual proposed cell layout.

01Ask what varies between cells of one material

Density, nominal conductivity, porosity and ignition threshold describe a material kind. Temperature, moisture, progress, timers and flags describe one cell now. A property lookup takes Material and returns its shared configuration; the cell stores only the material identity needed to select it.

This is a data-modeling decision with a direct memory consequence. Copying an entire property table into each cell increases memory without adding information. Conversely, storing one global temperature per material would prevent hot and cold instances from coexisting. Keep identity, shared rules and current state separate.

02Use signed temperature and bounded moisture

The design uses signed i16 temperature so subzero states and lava temperatures fit its chosen range. Moisture has a documented0–100 meaning, while u8 can represent more values; the type alone does not enforce that smaller domain. Clamp or validate transitions through a narrow operation rather than scattering unchecked writes.

The timer/progress/flag fields also need explicit meaning per material. A phase conversion should clear stale state that no longer applies. Adding a field because there is a spare byte is not enough; define who updates it, under which clock and how it survives movement or save/load.

03Measure layout rather than summing field widths

The proposed fields add up to8 bytes, but Rust struct layout can include alignment and padding, and default representation is not a stable disk protocol. Use size_of and align_of to inspect the actual selected definition. If the result misses the budget, investigate field ordering or a deliberate representation choice with tests.

Do not serialize raw struct memory as the public save format merely because its measured size is8. Padding, representation guarantees, invalid enum values and future changes make explicit encoding a separate responsibility. Today’s measurement is about in-memory budget, not compatibility.

04Give the rule table a small tested interface

Start with Air,Sand,Water,Stone and properties needed by the next density/heat fixtures. Return a compact property value by matching Material. Test that two cells of the same identity can retain different temperatures while reading identical conductivity.

For Air, the current design reads ambient rather than storing meaningful per-cell temperature. Keep that exception explicit so empty space does not accidentally participate in the same stored-temperature rule. The worked example demonstrates separation and size inspection; the final packed layout remains subject to the actual implementation’s constraints.

Walk through the working example

Complete focused example — src/main.rs

Download this worked example ↧

#[derive(Clone,Copy)]
enum Material { Air, Sand, Water, Stone }
struct Properties { density:u16, conductivity:u8 }
fn properties(m:Material)->Properties {
    match m {
        Material::Air=>Properties{density:0,conductivity:0},
        Material::Sand=>Properties{density:1600,conductivity:2},
        Material::Water=>Properties{density:1000,conductivity:4},
        Material::Stone=>Properties{density:2600,conductivity:3},
    }
}
struct Cell { temperature:i16,material:u8,moisture:u8,timer:u8,progress:u8,flags:u8,variant:u8 }
fn main() {
    let p=properties(Material::Sand);
    println!("sand density={}, conductivity={}",p.density,p.conductivity);
    println!("cell size={}, alignment={}",std::mem::size_of::<Cell>(),std::mem::align_of::<Cell>());
}

Read what each part does

  1. The material enum is used by the lookup; the raw identity byte in Cell requires an explicit validated mapping in production.
  2. Do not infer serialized representation from this struct.
  3. Fixture property scales must be documented before mixing numeric units.

Expected result

The selected definition normally reports size8 and alignment2 on the target, but the printed result is the evidence. Property numbers here are teaching fixture values, not final tuned conductivity.

Exact version numbers, paths and compiler wording may differ. Compare the behavior and file locations, not incidental output formatting.

01

Two temperatures, one material

Need a hint?

State varies independently of the property lookup.

Worked solution

Keep the two temperatures distinct while both property queries return the same conductivity. Do not encode “hot sand” as a completely unrelated material solely to store temperature.

Check the moisture domain

Need a hint?

Storage range and game-valid range are different.

Worked solution

u8 permits150, but the game domain caps moisture at100. Add a validated setter or bounded update and test the domain explicitly.

How to verify your result

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Cell size exceeds8

What is happening: Alignment/padding or extra fields changed the actual layout.

Try this: Measure size/alignment and revise the definition deliberately.

Every sand cell has the same temperature

What is happening: Changing state was placed in the material property table.

Try this: Store temperature per cell and properties per identity.

Moisture exceeds100 despite u8

What is happening: The narrower game domain was never enforced.

Try this: Validate/clamp updates through the chosen moisture operation.

Explain it without the example

Why is conductivity a material property but temperature cell state?

Reasoning to compare

Conductivity describes how that material exchanges heat. Temperature describes this particular cell now and can differ between cells of one material.
