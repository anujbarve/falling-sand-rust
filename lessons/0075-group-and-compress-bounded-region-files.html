Group and compress bounded region files

Compress a bounded payload, decode it exactly and reject expansion beyond the declared cell budget.

Previously: Define a versioned binary save format. Keep that working result available before starting this lesson.

Why we need this now

Uniform terrain often compresses well, but compression must not become an unbounded allocation path. A simple run-length experiment makes encoding, expansion and limits visible before choosing a production codec.

Your result: Compress a bounded payload, decode it exactly and reject expansion beyond the declared cell budget.

01Understand a run before choosing a library

Consider material IDs [0,0,0,2,2,1]. Run-length encoding records three zeros, two twos and one one. This is useful for uniform spans, while alternating values can expand. Therefore compression effectiveness is a property of data and codec, not a promise that every chunk becomes a few kilobytes.

Our teaching codec stores a one-byte count followed by a one-byte value. Runs are limited to 255 so a long uniform span becomes several runs. This is a small educational format, not an instruction to prefer it over LZ4 without measurement.

02Put bounds before allocation

The decoder receives a maximum output length. Before each extension it checks whether the next run fits. It also rejects odd byte counts and zero-length runs. These checks make malformed input a normal Result error instead of a large allocation or ambiguous stream.

For production the maximum follows from a validated region index, up to 32 by 32 chunks and the documented cell encoding. Do not trust a compressed payload’s self-reported uncompressed size as authority. The external format and configured limits supply that authority.

03Group chunks without confusing identifiers

A region contains sparse changed chunks, not necessarily all 1024 possible entries. Its index needs local chunk coordinates, payload offset/length and enough metadata to validate each entry. Reject duplicate coordinates, out-of-range slots and overlapping payload sections unless a sharing rule deliberately allows them.

Compression can apply per chunk or per whole region. Per-chunk compression supports selective loading; whole-region compression may improve ratio but amplifies reads and rewrites. Choose based on measured panning and autosave behavior, and record the choice before freezing the format.

04Test content, limits and cost separately

Round-trip testing proves fidelity. Corruption tests prove rejection. Size/time measurements characterize usefulness. None substitutes for the others. Run uniform stone, alternating cells and mixed temperature/moisture payloads; material IDs alone underestimate the real save’s entropy.

Before adopting a codec dependency, check its primary documentation for maximum-output controls and error behavior, pin its version and review its licence. The worked standard-library codec lets us learn the control flow without installing a package; it does not settle the production compression decision.

fn encode(data: &[u8]) -> Vec<u8> {
    let mut out = Vec::new();
    let mut i=0;
    while i<data.len() {
        let value=data[i]; let mut count=1_usize;
        while i+count<data.len() && data[i+count]==value && count<255 { count+=1; }
        out.extend_from_slice(&[count as u8,value]); i+=count;
    }
    out
}
fn decode(data: &[u8], max: usize) -> Result<Vec<u8>, &'static str> {
    if data.len()%2!=0 { return Err("truncated run"); }
    let mut out=Vec::new();
    for pair in data.chunks_exact(2) {
        let count=pair[0] as usize;
        if count==0 { return Err("empty run"); }
        let end=out.len().checked_add(count).ok_or("length overflow")?;
        if end>max { return Err("output limit"); }
        out.resize(end,pair[1]);
    }
    Ok(out)
}
fn main() {
    let input=vec![7;4096]; let packed=encode(&input);
    assert_eq!(decode(&packed,4096),Ok(input));
    assert!(decode(&packed,4095).is_err());
    assert!(decode(&[1],4096).is_err());
    println!("4096 uniform bytes -> {} bytes",packed.len());
}

Read what each part does

  1. Runs never exceed 255, so 4096 equal bytes become 17 runs, or 34 encoded bytes.
  2. checked_add prevents arithmetic overflow before applying the configured bound.
  3. Use the full encoded cell payload in real measurements, not only material IDs.

Expected result

4096 uniform bytes -> 34 bytes

Exact version numbers, paths and compiler wording may differ. Compare the behavior and file locations, not incidental output formatting.

Exercises you actually do

01

Find the bad workload

Encode 100 alternating zero/one bytes.

Need a hint?

Every run has length one.

Worked solution

The encoded output has 200 bytes, twice the input. A production format can choose an uncompressed representation when compression expands the data, with an explicit mode flag.

How to verify your result

Measure and report the expansion rather than claiming universal savings.

02

Reject a decompression bomb

Decode [255,0,255,0] with max=256.

Need a hint?

The second run would exceed the limit.

Worked solution

The first run yields 255 bytes. The second proposes 510, so the decoder returns output limit before resizing.

How to verify your result

The decoder returns Err and never produces a 510-byte result.

03

Index sparse chunks

A region has changed chunks at local coordinates (0,0) and (31,31). Must it store 1024 payloads?

Need a hint?

An index can describe only present entries.

Worked solution

No. Encode two validated entries and their payloads; absent chunks regenerate from the world’s generator version. Duplicate or out-of-range coordinates must be rejected.

How to verify your result

A sparse region round-trip restores both coordinates and no invented payloads.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Compression makes a save larger

What is happening: The scene has short runs or high entropy.

Try this: Measure actual cells and support a raw mode when useful.

Corrupt input allocates enormous memory

What is happening: The decoder trusts declared expansion.

Try this: Enforce a validated maximum before every output growth.

One chunk edit rewrites a huge region

What is happening: Storage granularity and compression granularity are coupled poorly.

Try this: Measure per-chunk indexed payloads versus whole-region compression and choose deliberately.

Explain it without the example

Why must decoded-size limits be enforced before allocating a claimed decompressed payload?

Reasoning to compare

A small malformed file may claim an enormous expansion. Bounds protect memory and make corruption a recoverable error.
