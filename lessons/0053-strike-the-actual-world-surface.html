Strike the actual world surface

The struck world cell changes as specified. The decorative bolt does not independently mutate material.

Previously: Ignite gunpowder and resolve a blast. Keep that working result available before starting this lesson.

Why we need this now

The lightning bolt is a drawing, but the strike is a world event. We must resolve what it hits before deciding heat or ignition. Otherwise an underground camera or a clipped bolt could change which cell receives the event.

Your result: The struck world cell changes as specified. The decorative bolt does not independently mutate material.

01Resolve the world receiver

The strike starts from the weather cloud-base concept and travels down to the first appropriate non-gas surface in its column. Use the existing world surface/exposure interface rather than scanning an infinite screen column. If the surface is outside active simulation, apply the explicitly chosen event policy instead of mutating frozen cells accidentally. A targeted lightning tool may select a cursor location under its own documented targeting rule, but natural lightning still resolves from weather and geometry.

02Separate material effects

A flammable hit can ignite after the approved heat/ignition check. Metal conducts the strike through its connected group under the current design. That group search is not identical to support across arbitrary rigid materials: only the relevant conductive connectivity should participate. A metal roof beside stone should not heat every connected mountain cell merely because both belong to a rigid support group. Keep a conductivity/contact predicate for the event search.

03Bound an event that sounds instantaneous

A “single bright frame” is a rendering duration, not permission for unlimited CPU work. A giant metal structure can span many chunks, so the conductive group operation needs the same kind of explicit cap/budget decision as support. Its order must not race normal cell phases. Queue the strike and apply the bounded effects serially or through owned outputs. A delayed thunder sound follows the event independently; it should not delay actual heat application.

04Build a roof and conductor fixture

Place a flammable target under an open column, another under a roof, and a connected metal strip. Resolve natural strikes above each. Verify the roof intercepts the first hit, the sheltered target stays protected unless heat/fire later spreads, and the strip follows the approved connected-heating rule. Then move only the camera and repeat with an identical active interior. The same world receiver should be selected; only the visible portion of the bolt changes.

fn first_surface(column_top_down: &[bool]) -> Option<usize> {
    column_top_down.iter().position(|occupied| *occupied)
}
#[test]
fn the_roof_intercepts_the_strike() {
    let column=[false,false,true,false,false,true];
    assert_eq!(first_surface(&column),Some(2));
    assert_eq!(first_surface(&[false,false,false]),None);
}

01

Reverse the coordinate convention

Why does this slice explicitly say top-down?

Need a hint?

World altitude and vector index direction may differ.

Worked solution

The helper searches from index zero. If the stored world column is bottom-up, use an appropriate reversed traversal or surface lookup. Documenting order prevents hitting the cellar before the roof.

How to verify your result

The fixture names and tests the traversal direction.

02

Limit conduction

Should a stone cell between two metal sections make them one conductive group?

Need a hint?

Choose the event’s material-connectivity rule.

Worked solution

Not under a metal-only connectivity rule. Test two strips with a stone gap and require only the struck connected section to receive the group heating, unless another approved rule says otherwise.

How to verify your result

A nonconductive gap breaks the group in the fixture.

03

Separate visual timing

If the bolt is off-screen, should its world heat effect disappear?

Need a hint?

Drawing and event resolution have different responsibilities.

Worked solution

No, if the receiver is active and the event is otherwise valid. A clipped visual does not cancel a resolved physical event. Off-region frozen behavior is governed by its separate policy.

How to verify your result

Changing draw visibility alone changes no receiver state.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Lightning hits through a roof

What is happening: Selection starts from the cursor or wrong traversal end.

Try this: Resolve the first world surface explicitly.

Entire terrain heats as one conductor

What is happening: The support-group predicate was reused for conductivity.

Try this: Search only the approved conductive connectivity.

Thunder timing changes ignition

What is happening: Audio callback drives physics.

Try this: Apply the strike in the simulation event phase; schedule sound as an output.

Explain it without the example

Why separate drawing a bolt from resolving the strike target?

Reasoning to compare

The visible effect may be clipped by the camera. Its physics target must still come from world geometry, not screen coordinates.
