Move material without duplicating it

Transfer a grain into empty space without creating or destroying a copy.

Previously: Handle a missing cell with match. Keep that working result available before starting this lesson.

Why we need this now

Changing a destination cell to Sand looks like movement only if the source stops being sand. A swap expresses the full occupancy transfer and avoids holding two simultaneous mutable element references while the vector is owned by one world.

Your result: Transfer a grain into empty space without creating or destroying a copy.

01State the conservation promise first

In a closed fixture with no painting, reactions or outflow, the number of sand cells should stay constant. That is the behavior we want before choosing an implementation. If a source contains Sand and a destination contains Air, the next state should contain Air at the source and Sand at the destination.

Writing only destination=Sand duplicates matter because the old source remains occupied. Clearing only the source destroys it. A visual test might still show a grain in roughly the right place, so count conservation is a separate assertion rather than something inferred from appearance.

02Use values for inspection, then one mutation

Because Material identity is Copy, read the two identities into local values or compare them through indexing. Once the movement condition is established, call cells.swap(source,destination). This exchanges the elements under one mutable access to the vector.

Trying to create &mut cells[source] and &mut cells[destination] simultaneously can be rejected because generic indices may coincide and the compiler cannot assume they are disjoint. swap is a standard interface whose implementation handles the aliasing contract. Use a safe operation that matches the intended transfer instead of reaching for unsafe pointers.

03Validate both indices before moving

The focused example uses two known-valid indices in a tiny vector. Runtime coordinates still pass through the checked mapping or world query. Moving from a source to itself should be either rejected or a documented no-op; it is not a successful fall. A blocked destination must leave both slots unchanged.

The movement helper returns bool to report whether it actually moved. That result will later help mark dirty rectangles or count activity. Do not infer success merely because the function was called. A movement attempt can fail for a normal reason such as a stone or occupied slot.

04Test state before and after the complete operation

Count Sand before the attempt, inspect the source/destination after it, and compare the count. Then run blocked, wrong-source and same-index cases. These tests describe the operation’s contract independently of its implementation.

When density exchanges arrive, a swap remains useful: heavier matter moves down while lighter matter takes its previous place. The condition becomes richer, but the paired occupancy transfer still must be complete. The simple Air/Sand fixture is therefore a foundation, not a disposable trick.

Walk through the working example

Complete focused example — src/main.rs

Download this worked example ↧

#[derive(Clone,Copy,Debug,PartialEq,Eq)]
enum Material { Air, Sand, Stone }
fn move_into_air(cells:&mut [Material],from:usize,to:usize)->bool {
    if from==to || from>=cells.len() || to>=cells.len() { return false; }
    if cells[from]==Material::Sand && cells[to]==Material::Air {
        cells.swap(from,to); true
    } else { false }
}
fn main() {
    let mut cells=vec![Material::Sand,Material::Air,Material::Stone];
    let before=cells.iter().filter(|m| **m==Material::Sand).count();
    assert!(move_into_air(&mut cells,0,1));
    assert_eq!(cells,[Material::Air,Material::Sand,Material::Stone]);
    assert!(!move_into_air(&mut cells,1,2));
    assert_eq!(before,cells.iter().filter(|m| **m==Material::Sand).count());
    println!("one grain moved; count preserved");
}

Read what each part does

  1. The focused helper checks bounds even though the fixture uses known indices.
  2. Identity comparisons do not consume the vector.
  3. The count assertion protects a different property than the location assertion.

Expected result

one grain moved; count preserved

01

Reproduce duplication

Replace swap with destination assignment in a copy of the helper and run the count assertion.

Need a hint?

The source still contains sand.

Worked solution

The count rises from1 to2. Restore swap or explicitly perform the correct paired state transfer. A correct final destination alone does not prove movement was valid.

How to verify your result

The conservation assertion catches the intentional bug.

02

Check a blocked attempt

Move the grain toward the Stone slot.

Need a hint?

A failed attempt must leave both cells unchanged.

Worked solution

The helper returns false, source stays Sand and destination stays Stone. Capture the full small vector before the attempt and assert equality afterwards.

How to verify your result

Blocked movement is a no-op rather than material destruction.

03

Name the next extension

How would water being displaced by sand change the helper?

Need a hint?

The transfer operation and eligibility test are different parts.

Worked solution

Keep a paired exchange, but replace the air-only condition with an explicitly approved kind/density rule. Do not make every dense object pass through rigid stone.

How to verify your result

The answer separates material-rule policy from storage mutation.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Sand count grows during falling

What is happening: The source was not cleared during transfer.

Try this: Use swap or a correct paired update and assert counts.

Borrow checker rejects two mutable indices

What is happening: The compiler cannot prove arbitrary indices differ.

Try this: Use slice swap or prove a safe disjoint split when that is actually needed.

Blocked movement erases matter

What is happening: Source mutation happened before destination validation.

Try this: Check the full eligibility condition before applying the transfer.

Explain it without the example

Why is a swap useful for moving sand into air?

Reasoning to compare

It relocates sand and moves air back to the source in one operation. Assigning only the destination would leave duplicate sand behind.
