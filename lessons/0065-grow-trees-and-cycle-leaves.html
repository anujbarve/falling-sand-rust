Grow trees and cycle leaves

A growing tree never overwrites a house. Detached leaves drift and eventually join the soil-formation cycle.

Previously: Restore grass after a fire. Keep that working result available before starting this lesson.

Why we need this now

Trees must be built from the same wood and leaf cells as everything else. Otherwise fire, support and a player’s brush cannot affect them consistently. A template supplies a simple growth direction while collision checks keep the living world from painting over a newly built house.

Your result: A growing tree never overwrites a house. Detached leaves drift and eventually join the soil-formation cycle.

01Represent a template as relative offsets

Store a small list of offsets from a sapling origin, each with a material to add. Trunk steps come before supported branch/leaf steps under the chosen template. A growth stage identifies the next candidate rather than allocating a complete invisible tree. The template is data, so an evergreen pine and a deciduous tree can share the growth mechanism while choosing different cells and leaf-cycle behavior. Avoid starting with a procedural branching research project when a few authored templates can prove the ecological loop.

02Validate every addition at the moment of growth

The world may change after the sapling appears. Before adding each cell, check target occupancy, active-region policy, attachment/support and any maximum height/density constraints. An empty space at planting time is not permission to overwrite a roof ten days later. If blocked, choose a declared policy: pause the stage, abandon that branch, or try an approved alternate. Keep it deterministic and bounded. The lab demonstrates a reservation-like check with a boolean occupancy buffer.

03Track living attachment without circular immortality

Rooted trunk wood and attached leaves stay in place; detached leaves become light powder. A local leaf-to-leaf rule can leave a floating loop that claims mutual attachment, much like the old support bug. Define living connectivity to an actual trunk/root source, using bounded search or maintained tree metadata as approved. Autumn detaches deciduous leaves; evergreen needles remain. Spring regrowth depends on a living tree source, not merely any leaf-coloured cell nearby.

04Keep growth and leaf cycles within slow-work bounds

A high calendar multiplier must not instantiate a whole tree in one unbounded operation. Advance at most the allowed stage/cell per executed tick and guard newly created targets from immediate further growth. Leaf litter eventually contributes soil formation under moisture/soil-contact rules, closing renewal with decay. Measure dense forests later; one template is cheap, but thousands of plants competing for targets and connectivity checks can change worst-case tick cost.

fn grow_one(occupied:&mut [bool], target:usize)->bool {
    let Some(slot)=occupied.get_mut(target) else { return false; };
    if *slot { return false; }
    *slot=true; true
}
#[test]
fn growth_does_not_overwrite_new_obstacles() {
    let mut world=[false,false,true,false];
    assert!(grow_one(&mut world,1));
    assert!(!grow_one(&mut world,2));
    assert!(!grow_one(&mut world,9));
    assert_eq!(world,[false,true,true,false]);
}

Exercises you actually do

Write a prediction or make an attempt before opening a solution. Use the hint if stuck; then compare reasoning and verify with the stated check. A different implementation is fine when it satisfies the same contract.

01

Build a trunk template

Write offsets for a three-cell vertical trunk in upward world coordinates.

Need a hint?

Offsets are relative to the sapling origin.

Worked solution

Use (0,0),(0,1),(0,2) if altitude increases upward. When drawing, convert those world y values into downward screen rows rather than reversing the growth data.

How to verify your result

Three growth visits place the intended vertical trunk without a sign error.

02

Block a future branch

Place a house cell where the next leaf would grow after the sapling starts.

Need a hint?

Validate at growth time, not only planting time.

Worked solution

The next growth visit must observe the occupied target and follow the documented blocked policy. The house remains intact.

How to verify your result

The obstacle’s material and count are unchanged.

03

Test evergreen behavior

Which state should autumn detach in the two variants?

Need a hint?

Needle identity is a variant, not an unrelated growth engine.

Worked solution

Detach deciduous leaf cells into litter behavior; retain evergreen needles attached under the chosen seasonal rule. Test both using the same tree template mechanism with different leaf variants.

How to verify your result

The evergreen fixture retains foliage while the deciduous one sheds.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Trees overwrite buildings

What is happening: Template occupancy was checked only at planting.

Try this: Validate each target immediately before committing growth.

Floating leaves remain attached forever

What is happening: Leaf adjacency is circular with no trunk source.

Try this: Anchor connectivity to living trunk/root data.

64x growth freezes the frame

What is happening: One visit expands all remaining template cells.

Try this: Limit work per executed tick and test blocked/dense cases.

Explain it without the example

Why must tree templates check occupancy at every growth step?

Reasoning to compare

The world can change after the sapling starts. Prechecking once does not prevent later growth from overwriting newly painted material.
