Separate absorbed moisture and surface wetness

Wet wood resists ignition and metal can satisfy the documented rust condition. The chosen moisture meaning is recorded in the milestone plan.

Why we need this now

Rain wets metal even though metal does not absorb water into pores. The design already needs moisture to control rust, so “porosity is zero” cannot mean “this surface is forever dry.” Before implementing more reactions we must give that field an unambiguous meaning.

Your result: Wet wood resists ignition and metal can satisfy the documented rust condition. The chosen moisture meaning is recorded in the milestone plan.

01Separate two physical ideas in the game model

Absorbed moisture is water held by porous material; surface wetness is a film/contact condition. They may share one compact field in this simplified game, but only if the interpretation is documented per material. A metal cell can have zero absorption capacity and still carry a wetness value used by rust and drying. This is a design choice, not a claim that a single u8 is a complete scientific water model. The lesson’s proposed lab separates the quantities so their behavior is visible.

02Decide whether a drop is consumed

For porous soil with spare capacity, a rain hit may raise absorbed moisture and consume a simulated water portion. For nonporous metal, the same hit can set a wetness duration or level while producing runoff. If the hit both fills the cell and creates a full extra water cell without accounting, water has been duplicated. Specify units: one grid water cell and one unit of moisture are not automatically equivalent. Use the game’s approximate humidity budget openly instead of hiding conversion ratios.

03Make drying conditional on exposure

Surface films can dry under warm exposed air while sheltered material dries more slowly. The weather system should pass context—sunlight, ambient, wind, shelter—into a bounded drying rule. Do not make material colour itself the wetness source. A darker swatch is an output of moisture state. Test metal under a roof, metal in rain and porous wood after rain stops, so the chosen semantics demonstrate why a house protects stored materials.

04Resolve the storage decision before packing

The eight-byte Cell layout is a constraint, but it does not justify ambiguous behavior. Options include interpreting moisture as absorbed content for porous cells and wetness for metal; allocating a separate bit/timer; or revising the layout after measurement. Write a small table of what each material reads and writes. The rust rule should consume the documented wetness path, not silently ignore its own prerequisite. Keep this marked as a milestone design proposal until agreed.

#[derive(Debug, PartialEq)]
struct Moisture { absorbed: u8, film: u8 }
fn rain_hit(state: &mut Moisture, capacity: u8) -> bool {
    state.film = 100;
    if state.absorbed < capacity {
        state.absorbed += 1;
        true
    } else { false }
}
#[test]
fn metal_gets_wet_without_absorbing() {
    let mut metal = Moisture { absorbed: 0, film: 0 };
    assert!(!rain_hit(&mut metal, 0));
    assert_eq!(metal, Moisture { absorbed: 0, film: 100 });
    let mut soil = Moisture { absorbed: 0, film: 0 };
    assert!(rain_hit(&mut soil, 80));
    assert_eq!(soil.absorbed, 1);
}

01

Saturate soil

What does rain_hit return when absorbed equals capacity?

Need a hint?

No spare pore capacity remains.

Worked solution

It returns false while refreshing the surface film. That result can tell the caller not to consume the hit as absorption and to use the approved runoff rule instead.

How to verify your result

The saturated fixture creates no additional absorbed unit.

02

Connect rust

Which field should rust read for this lab metal?

Need a hint?

Its absorbed content stays zero by design.

Worked solution

Rust should read film or an equivalent documented wetness condition. Reading absorbed would leave metal permanently below the wetness threshold.

How to verify your result

Wet metal can advance rust while a dry control cannot.

03

Pack carefully

Propose one-field production storage without changing the visible rules.

Need a hint?

Different materials may interpret the field differently if the table is explicit.

Worked solution

For porous cells let moisture mean absorbed content; for nonporous metal let it mean surface wetness. Specify rain, drying and conversion behavior for each case and test that transitions reset interpretation correctly.

How to verify your result

A material-property table names every read/write meaning.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Metal never rusts

What is happening: Its wetness rule requires positive porosity.

Try this: Give rain/contact an explicit nonporous surface-wetting path.

Rain doubles water

What is happening: One hit is counted as absorbed and full runoff.

Try this: Specify the hit accounting and choose one consumed/runoff outcome.

Wet colour persists after drying

What is happening: Renderer caches a tint independently of current moisture.

Try this: Derive coherent tint from the current documented state.

Reasoning to compare
