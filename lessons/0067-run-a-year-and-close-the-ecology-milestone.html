Why we need this now

A single wet beam can pass its test while the whole world still ends a year as a lifeless dry basin. The ecology milestone needs both narrow fixtures and a long-run scene. It also needs evidence across seeds, because random opportunities can make one demonstration look healthier than the underlying rule.

Your result: All required seeds pass or failures become tracked design work. Lake level stays within the specified 20 percent bound in the acceptance fixture.

01Separate regression and reliability questions

A fixed regression seed recreates a known failure exactly. The 32-seed reliability suite asks whether each accepted scenario succeeds across a documented set of distinct sequences. Both are deterministic tests when the seeds and multiplier histories are fixed. Neither makes randomness disappear; they provide repeatable evidence over chosen cases. Do not keep changing seeds until a flaky assertion turns green, and do not claim mathematical certainty from a finite sample.

02Use crafted terrain before the generator exists

M3 comes before M4 procedural generation. Build the plains-and-lake fixture directly with a known bowl, saturated underlying soil, stable slopes, grass/tree sources and climate inputs. Store the fixture parameters in code and reuse them in the episode scene. This prevents a later generator dependency from blocking ecological work and makes any water-level change easier to attribute. A handcrafted scene is valid evidence for the scoped M3 gate, not proof that every future generated lake is stable.

03Measure multiple outputs at the end

The design requires grass, trees and water remaining, plus lake level within 20 percent of its start in the acceptance fixture. Measure water volume and surface height carefully: a one-cell surface shift can have different volume meaning depending on bowl shape. Record starting and final values using the agreed metric, vegetation counts and any cap/overload events. A screenshot of one surviving green pixel is not sufficient evidence that the ecological loop is healthy and readable.

04Make failure diagnostic rather than merely red

When a seed fails, report which condition failed, first divergence time if available, climate history, step/world tick counts and water-accounting totals. The cause may be absent regrowth sources, evaporation scale, a frozen-region test boundary or stage-skipping under high multipliers. Keep the smallest failing seed/fixture as regression. Then rerun the full reliability set only after a rule change, preserving the original case so the fix cannot hide a new failure elsewhere.

fn within_twenty_percent(start:u64,end:u64)->bool {
    if start==0 { return end==0; }
    let difference=start.abs_diff(end);
    u128::from(difference)*100 <= u128::from(start)*20
}
#[test]
fn water_tolerance_has_explicit_boundaries() {
    assert!(within_twenty_percent(100,80));
    assert!(within_twenty_percent(100,120));
    assert!(!within_twenty_percent(100,79));
    assert!(!within_twenty_percent(100,121));
}

Read what each part does

  2. The helper accepts exact 20-percent loss/gain and rejects 21 percent. Its integer arithmetic avoids floating rounding in this tolerance check. The actual lake metric must be chosen before collecting values.

01

Keep the metric stable

Can a test start with water volume and finish with surface altitude?

Need a hint?

The comparison needs one unit.

Worked solution

No. Pick the metric required by the accepted gate and record both endpoints in that same unit. Supplement with the other metric if useful, but do not mix them inside one percentage.

How to verify your result

02

Do not average away failure

31 seeds pass and one loses all trees. What does the current all-32 gate do?

Need a hint?

Read the acceptance rule literally.

Worked solution

It fails. Retain the failing seed and diagnose the tree/recovery/climate path. An average vegetation count cannot replace an all-seed condition.

How to verify your result

Distinguish a passing lab

Would this tolerance helper passing prove a healthy year?

Need a hint?

Worked solution

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

The year test depends on nonexistent lakes

What is happening: It accidentally calls the future procedural generator.

Try this: Use a stable hand-built lake fixture for M3.

One seed fails intermittently

What is happening: Frame timing or unrecorded inputs enter the headless test.

Try this: Fix elapsed/multiplier inputs and compare tick-by-tick.

Lake level passes but terrain is ruined

What is happening: The gate measures water alone.

Try this: Retain vegetation, silhouette and long-run material observations too.

Explain it without the example

Why keep both one fixed regression seed and a 32-seed suite?

Reasoning to compare

The fixed seed gives repeatable diagnosis. Multiple seeds detect reliance on one fortunate random sequence; neither replaces the other.
