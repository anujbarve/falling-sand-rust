Commit a complete save generation

Simulate crashes at save stages and always recover a complete old or complete new generation.

Previously: Snapshot a running world without changing it. Keep that working result available before starting this lesson.

Design choice to settle. The current specification leaves a decision here. The example makes the mechanism concrete; document the chosen behavior before treating it as the final game rule.

Why we need this now

A single writer prevents competing writes, but a crash can stop it between any two operations. The loader needs a commit rule that identifies a complete world rather than picking whichever region files happen to be newest.

Your result: Simulate crashes at save stages and always recover a complete old or complete new generation.

01Find the multi-file failure

Suppose the world has regions A and B plus an index. Replacing A successfully and crashing before B leaves new A with old B. Per-file rename did its job, but the world transaction failed. A single writer serializes the operations; it does not combine them into one indivisible operation.

Use immutable generation-specific files or directories. Write all new payloads under generation N+1 without overwriting the committed N. The new manifest names exactly which immutable files form the new world. Do not ask the loader to guess from timestamps.

02Commit only the reference to complete data

The logical protocol is prepare payloads, verify/sync required data, write a manifest referencing those payloads, then publish the commit reference. Before commitment, load generation N. After commitment, load N+1 only if its validated files are complete. Retain N until the new state is known recoverable.

This is a design protocol, not a claim that one std::fs call provides power-loss durability everywhere. File synchronization, directory metadata synchronization and platform rename behavior must be checked on supported filesystems. A crash-recovery simulation proves logical ordering; real fault testing validates the implementation.

03Validate the manifest as untrusted input

A manifest needs a generation ID, format/generator identity and bounded region entries with integrity metadata. Validate entry count and paths; entries must resolve inside the world’s own save directory. Reject missing, truncated or mismatched payloads. If the newest committed candidate is invalid, use the explicit previous committed generation policy.

Avoid inventing a sophisticated recovery scheme before this two-generation model works. Keep errors visible and preserve both candidates until recovery is understood. Automatic cleanup must never delete the sole coherent generation because the newest directory merely exists.

04Make failure injection a normal test input

The worked model separates payload-written from committed. It deliberately does not touch the filesystem, allowing every stopping stage to be tested instantly and deterministically. Extend it with checksums and two region IDs, then connect the same state machine to actual writer operations.

Inject failures after each region write, after manifest write and before/after commit publication. A successful normal save is only one path through this state machine. Record the selected generation and complete world hash after every recovery case.

#[derive(Default)]
struct Store { committed: u64, complete: Vec<u64> }
fn recover(store: &Store) -> Option<u64> {
    store.complete.iter().copied().find(|id| *id==store.committed)
}
fn save_model(crash_after: u8) -> Store {
    let mut s=Store {committed:1,complete:vec![1]};
    if crash_after==0 { return s; }
    // All payloads and manifest for generation 2 now validate.
    s.complete.push(2);
    if crash_after==1 { return s; }
    // Publish the commit reference only after completion.
    s.committed=2;
    s
}
fn main() {
    assert_eq!(recover(&save_model(0)),Some(1));
    assert_eq!(recover(&save_model(1)),Some(1));
    assert_eq!(recover(&save_model(2)),Some(2));
    println!("every interruption selects a complete generation");
}

Read what each part does

  1. complete is the model’s validated-data set, not a directory-exists test.
  2. The commit reference chooses one complete generation. An uncommitted new payload cannot accidentally become current.
  3. This pure state-machine model is a logic test, not an implemented durable filesystem writer.

Expected result

every interruption selects a complete generation

Exact version numbers, paths and compiler wording may differ. Compare the behavior and file locations, not incidental output formatting.

Exercises you actually do

01

Interrupt the region writes

Add two separate payload-written flags and crash after the first.

Need a hint?

A generation is complete only if all referenced payloads validate.

Worked solution

Keep committed=1 after only new A exists. Do not include generation 2 in complete until B and the new manifest are validated too.

How to verify your result

Recover returns generation 1 and its full original world hash.

02

Reject a corrupt commit target

The commit reference names generation 2, but one payload checksum fails.

Need a hint?

Directory existence is insufficient.

Worked solution

Validation must reject generation 2. Under the approved recovery policy, select the retained previous committed generation 1 and report that recovery occurred.

How to verify your result

No mixture of region versions is loaded.

03

Explain a safe cleanup

When may old generation 1 be deleted?

Need a hint?

Think about crash windows and retained recovery policy.

Worked solution

Only after generation 2 is durably committed and validated under the platform-specific writer protocol, and only if the retention policy still keeps the required recovery history.

How to verify your result

Fault-injection tests never leave zero coherent recoverable generations.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Some chunks revert after a crash

What is happening: The loader mixes independently renamed region files.

Try this: Use a committed manifest selecting an entire coherent generation.

Newest directory is loaded although incomplete

What is happening: Recency is used as a commit signal.

Try this: Separate generation creation from explicit commit publication.

Recovery deletes the only good world

What is happening: Cleanup runs before new generation validation/durability.

Try this: Retain the prior committed state until the new protocol is fully complete.

Explain it without the example

Why is a single disk-writer thread insufficient for crash consistency?

Reasoning to compare

It orders writes but a crash can interrupt that order. The loader still needs a way to identify which complete set of files belongs together.
