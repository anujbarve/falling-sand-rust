Draw weather without changing its physics

Render rain that respects shelter while changing graphics density leaves precipitation physics unchanged.

Previously: Make material states readable without texture noise. Keep that working result available before starting this lesson.

Design choice to settle. The current specification leaves a decision here. The example makes the mechanism concrete; document the chosen behavior before treating it as the final game rule.

Why we need this now

The weather simulation already applies rain at the surface. Decorative streaks should help the viewer read that weather; they must not add a second source of water or appear inside a supposedly dry shelter.

Your result: Render rain that respects shelter while changing graphics density leaves precipitation physics unchanged.

01Draw the causal boundary first

Use a debug cross-section with a roof and an open hillside. Mark the exposed surface for each column. Rain simulation uses its approved surface rule, while visual streaks are clipped before they pass into sheltered space. The two systems share world meaning but do different work.

A renderer may draw 300 or 1400 streaks depending on graphics settings. The same tick/input sequence must still produce the same wetness and runoff. If lowering visual quality dries the hillside, the simulation is counting decorative particles as real rain.

02Freeze a deterministic visual frame

For visual comparisons use a separate deterministic decoration seed/time. Generate candidate streak positions, rasterize short diagonal lines in art pixels and clip them against the view and shelter. The static frame in this experiment needs no animation loop to prove the clipping condition.

Keep decoration randomness separate from physics randomness. Adding one extra streak should not consume a random number that changes the next fire or growth decision. Use named independent streams or coordinate hashes with distinct purpose tags.

03Choose layering without breaking pixel rules

The approved reference has far and near streak tones; near streaks are composited last. Opacity blending of hard art pixels is allowed by the rain recipe; spatial blur is not. Clouds, snow and fog treatments remain proposals until approved. Fog should affect visibility coherently without softening the actual geometry boundaries.

Rendered sea ripples also stay cosmetic in v1. They may colour occupied surface-water pixels but must not create water into air or carry sand unless a later mechanical erosion rule explicitly does so. Keep every weather visual’s read-only relationship to simulation state visible in the code.

04Test the shelter edge and quality switch

A single streak can cross several columns, so clipping only its starting point is insufficient. Test every rasterized art pixel against the surface/shelter at that column. At the roof edge, exposed pixels outside the roof can continue while protected pixels beneath it are omitted.

The helper below reports which pixels from a diagonal candidate survive a small shelter mask. Integrate it with your integer line rasterizer, not an antialiased graphics stroke. Then replay the same rain simulation with two decorative densities and compare world hashes.

Download this worked example ↧

fn visible_rain(x:i32,y:i32,surface:&[i32])->bool {
    x>=0 && (x as usize)<surface.len() && y>=0 && y<surface[x as usize]
}
fn main() {
    // Columns 2 and 3 have a roof at row 4; others have ground at row 10.
    let surface=[10,10,4,4,10,10];
    assert!(visible_rain(2,3,&surface));
    assert!(!visible_rain(2,4,&surface));
    assert!(!visible_rain(2,8,&surface));
    assert!(visible_rain(4,8,&surface));
    assert!(!visible_rain(-1,0,&surface));
    for (x,y) in [(4,2),(3,4),(2,6),(1,8)] {
        println!("pixel ({x},{y}) visible={}",visible_rain(x,y,&surface));
    }
}

Read what each part does

  1. These rows increase downward in the art mask; derive them from world altitude with the approved conversion.
  2. Each candidate pixel is checked, so a streak cannot pass through a roof just because its start was exposed.
  3. The function returns visibility only. It never changes moisture or creates Material::Water.

Expected result

The candidate pixel above open ground survives; pixels at or beneath the roof are rejected.

Exact version numbers, paths and compiler wording may differ. Compare the behavior and file locations, not incidental output formatting.

01

Lower the graphics quality

Replay a rain fixture with 100 and 1400 decorative streaks. Which state should match?

Need a hint?

Compare the complete simulated state, not the rendered frame.

Worked solution

World material/moisture/temperature/counters match for identical simulation inputs. Only the image changes. Independent decoration RNG prevents physics-stream consumption differences.

How to verify your result

The world hashes match while image hashes differ.

02

Fix the start-only clip

A streak begins above a roof but ends beneath it.

Need a hint?

A valid starting pixel does not validate the full segment.

Worked solution

Rasterize its path and check visibility at each art pixel, stopping/omitting pixels when they enter shelter according to the approved mask.

How to verify your result

No rain pixels appear below the roof in the fixture.

03

Keep waves cosmetic

A water ripple colours one air pixel above the true surface.

Need a hint?

The art spec forbids decorative water from changing the apparent collision boundary.

Worked solution

Confine the ripple colour to occupied surface-water pixels. Mechanical water movement remains in the simulation, and v2 shoreline erosion is a separate rule.

How to verify your result

The visible occupied boundary agrees with the cell fixture.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Rain appears in rooms

What is happening: Streaks are composited without a world shelter mask.

Try this: Clip each rasterized pixel against exposed surfaces including roofs.

Quality presets change flood rate

What is happening: Decorative drops mutate simulation or share a consumed RNG stream.

Try this: Make decoration read-only and use independent deterministic random inputs.

Rain edges look smeared

What is happening: The renderer uses antialiased strokes or filtering.

Try this: Rasterize on the art grid and present with nearest filtering.

Explain it without the example

Why should changing a rain graphics setting leave soil wetting unchanged?

Reasoning to compare

The setting controls decoration. Simulation precipitation belongs to the weather rules and must not depend on how many streaks are drawn.
