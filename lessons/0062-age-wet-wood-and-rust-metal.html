Age wet wood and rust metal

Wet fixtures visibly decay within their specified deadlines, dry controls do not, and intermediate states remain observable.

Previously: Close drying seepage and evaporation loops. Keep that working result available before starting this lesson.

Why we need this now

A wet hut should age visibly while a dry control remains sound. The game needs intermediate rotten wood and rust powder, not merely a timer that deletes every old structure. We already have slow-work opportunities; now we connect them to conditional progress and explicit material transitions.

Your result: Wet fixtures visibly decay within their specified deadlines, dry controls do not, and intermediate states remain observable.

01Progress is conditional history

A slow visit should first check the material’s current qualifying condition, such as moisture above a threshold. If it qualifies, increase progress using the chosen fixed-point/integer rate; otherwise apply the approved stop/recovery rule. Decide whether dry periods pause or reverse accumulated rot. The spec establishes wetness dependence but not every recovery coefficient, so record that tuning decision rather than invent a universal physical law. A dry control catches accidental unconditional aging.

02Cross one stage at a time

Wood reaches a rot threshold and becomes RottenWood. That new material has different hardness/support consequences and later crumbles into Soil. Metal reaches its threshold and becomes Rust powder, which can fall or wash away. Reset or reinterpret progress at each material transition and prevent another slow transition in the same executed tick. A stage cap must account for current progress so an addition cannot overshoot or wrap the u8. Distinct sample picks do not by themselves protect newly modified neighbours.

03Read the correct wetness state

Metal has zero porosity in the material properties, so rust must use the approved surface-wetness path from the earlier lab. The same field can be interpreted per material only if conversion rules are clear. For wood, absorbed moisture and heat drying influence ignition as well as rot. Place wet and dry beams in matching environments and record moisture alongside progress. Otherwise a failed rot test may actually be a drying or initialization bug.

04Verify visible states and structural consequences

A test that skips directly to final Soil does not show that RottenWood was ever observable. Record first entry into each stage and retain the intermediate state for at least the allowed slow-update timing. Rotten wood should weaken support/impact according to the material rule rather than preserve normal wood hardness. Rust removes whole metal cells under this grid model, so a sheet becomes thinner by losing outer cells, not through subpixel geometry. Review the actual four-pixel rendering as well as state counts.

#[derive(Clone,Copy,Debug,PartialEq)]
enum Material { Wood, RottenWood, Soil }
fn decay(material:Material,progress:u16,wet:bool)->(Material,u16) {
    if !wet { return (material,progress); }
    let next=progress.saturating_add(10);
    if next<100 { return (material,next); }
    match material {
        Material::Wood=>(Material::RottenWood,0),
        Material::RottenWood=>(Material::Soil,0),
        Material::Soil=>(Material::Soil,0),
    }
}
#[test]
fn one_visit_crosses_only_one_stage() {
    assert_eq!(decay(Material::Wood,95,true),(Material::RottenWood,0));
    assert_eq!(decay(Material::Wood,95,false),(Material::Wood,95));
}

01

Keep an intermediate stage

Why return immediately after Wood becomes RottenWood?

Need a hint?

The new material must not consume the same opportunity again.

Worked solution

Returning prevents the same visit from processing the next stage. The full slow-pass guard must also prevent a later target/pick from processing that cell again during the same executed tick.

How to verify your result

The test records a RottenWood state between Wood and Soil.

02

Test dry interruption

Wet progress reaches 50, then the cell dries. What happens under this lab policy?

Need a hint?

The first branch returns unchanged state.

Worked solution

It stays at 50 until wet again. This is an explicit pause policy; if production chooses recovery, replace it with a tested decrement and document the decision.

How to verify your result

The test distinguishes pause from decay recovery.

03

Make rust visible

How should a metal sheet become thinner on this cell grid?

Need a hint?

Geometry is discrete at one material per cell.

Worked solution

Exposed metal cells convert to Rust powder and move away, leaving fewer occupied metal cells. Do not claim a subcell thickness simulation that the grid does not represent.

How to verify your result

Metal count decreases through visible rust/removed-cell states.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

Dry houses rot anyway

What is happening: Progress increments before checking moisture.

Try this: Make qualification the first condition and retain a dry control.

Rot skips its visible state

What is happening: Progress is reused immediately in a loop over stages.

Try this: Clamp and stop at the next transition.

Rust test never advances

What is happening: Metal cannot acquire the wetness condition it reads.

Try this: Connect the earlier nonporous surface-wetting rule.

Explain it without the example

Why test a dry control alongside a wet decay scene?

Reasoning to compare

It distinguishes conditional weathering from an unconditional age timer. A wet scene passing alone does not prove moisture matters.
