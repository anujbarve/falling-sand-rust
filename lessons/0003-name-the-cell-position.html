Name the cell position

Store a cell’s column and row in named values and calculate its drawing position.

Previously: Create and run the game package. Keep that working result available before starting this lesson.

Why we need this now

A cell needs a remembered position before it can move. Hardcoding numbers everywhere would make a grain’s identity disappear into arithmetic. Bindings let us name the quantities first, then derive drawing coordinates from them.

Your result: Store a cell’s column and row in named values and calculate its drawing position.

01Begin with the quantity, not the keyword

Imagine a grain at column 12 and row 5. Those are two counts in our teaching grid. They are not screen pixels yet. A binding associates a name with a value: let column = 12;. Read it as “bind the value 12 to the name column.” The semicolon ends the statement. Naming both coordinates makes the program’s assumptions visible before we introduce graphics.

Rust can infer the integer type in this simple example. We will annotate types explicitly in the numeric-types lesson. Today the important relationship is that later expressions can use the binding’s name instead of repeating the original literal. If you change column in one place, every expression using that binding sees the value selected there.

02Follow the program in order

The two let statements execute before the print calls. println!("Cell: {column}, {row}"); inserts the named values into the formatted text. The punctuation inside the string is output; the braces name the values to insert. This formatting mechanism is not a variable declaration and does not change the stored values.

Trace the example aloud: first column receives 12, then row receives 5, then the first message uses both. We do not have a graphical cell yet; the terminal output is a small observable model of the state that a later renderer will read. Keep the trace short enough to do mentally before running the program.

03Derive pixels from cells

The design gives one simulation cell a width of four physical pixels. In our temporary low-DPI teaching window, drawing units match that footprint. The cell at column 0 starts at x=0; column 1 starts at x=4; column 2 starts at x=8. The pattern is multiplication: screen_x = column * cell_size.

For column 12, 12 times 4 gives 48. This is a derived position, not an independent fact to memorize. If we changed column to 13, the drawing position would become 52. If we changed cell_size instead, every grid step would be farther apart. Position and scale therefore deserve separate names. The production renderer will later make the physical/DPI distinction explicit.

04Make one controlled change at a time

Run the example, then change only column. Predict which printed values change. Restore it, change only row, and predict again. Finally introduce let cell_size = 4; and replace the repeated 4 in the expression. This is a small refactor: the output stays the same while the intent becomes clearer.

Do not add motion yet. A useful first lesson about variables ends with a stable mapping from named state to an observable result. Once you can change an input and correctly predict the output, the next lesson can ask why some bindings are allowed to change during execution and others are not.

Read → predict → run → change

Walk through the working example

Complete focused example — src/main.rs

Download this worked example ↧

fn main() {
    let column = 12;
    let row = 5;
    let cell_size = 4;
    let screen_x = column * cell_size;
    let screen_y = row * cell_size;
    println!("Cell: {column}, {row}");
    println!("Drawing position: {screen_x}, {screen_y}");
}

Read what each part does

  1. cell_size is one shared conversion factor.
  2. screen_x and screen_y are computed values, not special drawing commands.
  3. println! lets us inspect state before a renderer exists.

Expected result

Cell: 12, 5
Drawing position: 48, 20

Exact version numbers, paths and compiler wording may differ. Compare the behavior and file locations, not incidental output formatting.

01

Move the description

Make the stored position column 20, row 7 without editing the conversion expressions.

Need a hint?

Change only the two input bindings.

Worked solution

let column = 20;
let row = 7;

The unchanged conversion then produces drawing position 80,28. These lines replace the corresponding bindings inside main; they are not an additional complete program.

How to verify your result

The terminal reports cell 20,7 and drawing position 80,28.

02

Separate spacing from position

Introduce cell_size if missing, set it temporarily to 8, then restore 4.

Need a hint?

The coordinate is a cell count; scale is another input.

Worked solution

With column 12 and row 5, size 8 produces 96,40. Neither cell coordinate changes. Restore size 4 because the actual game style fixes the cell footprint; the temporary change was a units experiment.

How to verify your result

You can explain why position in cells stayed the same while drawing coordinates changed.

03

Explain a name typo

Replace one use of column with colum and run cargo check.

Need a hint?

The compiler resolves exact names in scope.

Worked solution

The misspelled name has no binding. Repair the use to column, rather than introducing a second accidental variable. Read the diagnostic’s location and possible suggestion.

How to verify your result

The repaired program compiles and the original output returns.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

cannot find value in this scope

What is happening: A name is misspelled or used before its declaration.

Try this: Compare the exact spelling and keep the binding before its uses.

The output literally contains braces

What is happening: The formatting string or escaped braces were changed.

Try this: Use a valid println! format string with the existing binding names.

Changing row does not affect screen_x

What is happening: That is expected: x is derived from column.

Try this: Inspect the dependency of each expression instead of expecting all outputs to change.

Explain it without the example

What does multiplying a cell column by 4 represent in our teaching window?

Reasoning to compare

It converts a count of cells into a drawing coordinate when each cell is four pixels wide. The cell coordinate and drawing coordinate use different units.

Self-check only: test a prediction or ask your tutor if anything still feels arbitrary.

Finish with evidence

The reported drawing x coordinate is 48. Changing column changes that result while row stays the same.
