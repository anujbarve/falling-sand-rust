Decide whether a cell may fall

Use a boolean condition to distinguish a falling grain from a grain already resting above a floor.

Previously: Extract a coordinate conversion function. Keep that working result available before starting this lesson.

Why we need this now

Movement is not merely adding to a coordinate. A grain must first decide whether the proposed region is available. An if condition gives us the first explicit rule in the simulation: above the landing row it may move; at the landing row it must rest.

Your result: Use a boolean condition to distinguish a falling grain from a grain already resting above a floor.

01Define the boundary in cell units

Let floor_row be 160, meaning the floor starts at grid row 160. A grain occupies one row of cells. Its highest allowed top row is therefore 159: occupying row 160 would overlap the floor. This one-row offset follows from the footprint, not from a mysterious correction constant.

Keep floor_row in cell units, not drawing pixels. The renderer later multiplies it by four. If you compare row 159 to a floor drawing coordinate of 640, the code may compile because both are integers, yet the comparison would use incompatible meanings. State the units before writing the condition.

02A comparison produces a boolean

The expression row < floor_row - 1 asks whether the grain is above its last legal row. It evaluates to a bool: true or false. if uses that result to choose which branch executes. When row is 158, the comparison is true; at 159 it is false.

The comparison does not itself change row. It is a question about the present state. This distinction will become important when we add a proposed movement distance: “currently above the floor” is different from “the entire proposed path is clear.” Today we isolate the first question with printed output.

03Trace both branches, including equality

Run the example with row 158, then 159, then 160. The first should report moving; the latter two use the non-moving branch. But row 160 is already invalid input for this fixture, not a legitimate resting position. A branch choosing not to move cannot repair every invalid starting state automatically.

Try changing < to <= and examine the equality case. The modified condition treats row 159 as movable, which can allow overlap if you later add a step. Boundary tests are useful because the difference between two comparison operators is often invisible in the middle of the world.

04Use a terminal decision before graphical motion

A printed word is enough to verify the condition today. We will later turn the branch into a mutation and add destination clamping or path inspection. Separating decision from movement keeps the source of an error visible: first establish what counts as blocked, then implement what happens when free.

For the episode, draw three simple cell rows or use the verified diagram: a grain above the landing row, a grain touching the floor, and an invalid grain overlapping it. Ask viewers to predict the condition result before running. This is a small piece of simulation reasoning they can reuse for walls, liquids and brush bounds.

Walk through the working example

Complete focused example — src/main.rs

Download this worked example ↧

fn main() {
    let row = 158;
    let floor_row = 160;
    if row < floor_row - 1 {
        println!("moving");
    } else {
        println!("resting or invalid starting state");
    }
}

Read what each part does

  1. The condition asks about state; it performs no mutation.
  2. floor_row - 1 derives from the grain occupying one cell row.
  3. Invalid input is not silently declared physically correct.

Expected result

With row=158 the program prints moving. With row=159 it chooses the other branch.

Exact version numbers, paths and compiler wording may differ. Compare the behavior and file locations, not incidental output formatting.

Exercises you actually do

01

Check equality

Test row 159 using < and then <=. Predict before running.

Need a hint?

The grain at 159 already touches the floor.

Worked solution

With <, the move condition is false. With <=, it becomes true, which is too permissive for adding another downward row. Restore < after the experiment.

How to verify your result

Your explanation uses the cell footprint to justify the operator.

02

Name the decision

Bind the comparison to let can_fall and use if can_fall.

Need a hint?

The intermediate value has type bool.

Worked solution

let can_fall = row < floor_row - 1;
if can_fall {
    println!("moving");
}

This changes readability without changing the condition. It is useful when the name makes the rule clearer, not as compulsory extra syntax.

How to verify your result

The output matches the original condition.

03

Reject an invalid start

Add a distinct branch reporting invalid when row >= floor_row.

Need a hint?

Check invalid state before the ordinary fall/rest distinction.

Worked solution

if row >= floor_row {
    println!("invalid");
} else if row < floor_row - 1 {
    println!("moving");
} else {
    println!("resting");
}

Place these branches inside main after the bindings.

How to verify your result

All three test positions receive meaningful classifications.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

A resting grain falls into the floor

What is happening: An equality case was allowed or destination movement was not constrained.

Try this: Check the top-row convention and test the exact contact row.

The condition always seems true

What is happening: Cell rows may be compared to pixel values.

Try this: Write units next to each binding and convert only at rendering boundaries.

expected bool

What is happening: The if condition is a numeric value instead of a comparison.

Try this: Use an explicit comparison that evaluates to true or false.

Explain it without the example

Which position should stop a one-cell grain when the floor starts at row 160?

Reasoning to compare

Its top row stops at 159. The cell occupies one row; moving to 160 would overlap the floor.
