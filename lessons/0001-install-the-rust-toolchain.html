Install the Rust toolchain

Run rustc, Cargo and rustup successfully in a fresh terminal, and identify the job of each tool.

No programming experience is assumed. Start with the macOS path if you are using your MacBook.

Why we need this now

Before our world can contain a falling grain, the computer must be able to turn Rust source into a runnable program. Today we install that toolchain and prove it works. A successful download alone is not the finish line: a new terminal must find the commands and the native linker must be available.

Your result: Run rustc, Cargo and rustup successfully in a fresh terminal, and identify the job of each tool.

01Begin with the terminal, not the installer

On your Mac, press Command–Space, type Terminal, and open it. The text before the cursor is the shell prompt; it is not part of a command. In a prompt such as (base) anujbarve@anujs-MacBook-Air rusty %, rusty is the current folder and % marks where you type. The (base) prefix usually comes from a Conda environment; it does not mean Rust is installed.

Type pwd and press Return. This prints the current working directory. Type rustc --version, cargo --version, and rustup --version, each on its own line. If all three report versions, skip installation and verify the active toolchain with rustup show active-toolchain. Do not overwrite a working setup simply to follow a video.

02What exactly are we installing?

The installer is rustup, which downloads and selects Rust toolchains. rustc is the Rust compiler: it translates source instructions into compiled output. cargo manages a package, builds dependencies, invokes the compiler, and runs development tasks. These tools work together, but they are not interchangeable.

Building a native executable also needs a linker and system development files. On macOS, check xcode-select -p. If the developer tools are missing, run xcode-select --install and complete the Apple dialog. This is separate from installing the full Xcode application. Keep this step visible in the recording: viewers often have Rust installed but cannot link their first executable.

03Install on macOS, then start a fresh shell

Use the official rustup command shown below. It downloads the installer over HTTPS and executes it in a shell. Read the installer prompts and choose the default stable installation unless you already have a deliberate toolchain setup. The installed files normally live under your user account, with command shims in $HOME/.cargo/bin.

After installation, close and reopen Terminal. Alternatively, for the current POSIX-style shell, run source "$HOME/.cargo/env". Then repeat all three version checks. The version strings and hashes will change over time; the important observation is that each command is found and reports its own version. command -v cargo tells you which executable the shell is resolving. If it points somewhere unexpected, inspect that before editing shell configuration blindly.

04Windows and Linux viewers: same tools, different native prerequisites

On Windows, use the installer linked from the official Rust installation page. Choose the documented MSVC setup and complete its Visual Studio C++ build tools requirements. Open a fresh PowerShell window and run the same version commands. Do not paste the macOS source command into PowerShell; its shell syntax is different.

On Linux, the rustup installation command is the same as macOS, but native development packages come from the distribution. Ubuntu commonly uses sudo apt update followed by sudo apt install build-essential; other distributions use their own package names and managers. Install only the prerequisites relevant to your system. The goal across platforms is identical: a compiler, Cargo, toolchain management, and a working native linker. The next lesson proves them together by compiling a real program.

05macOS command blocks: checks first, installation only if missing

Run this first block one line at a time. These are checks, not installation commands:

rustc --version
cargo --version
rustup --version
xcode-select -p

If the Rust commands already work, do not run the Rust installer. If Apple developer tools are missing, run the following and finish the Apple dialog:

xcode-select --install

Only when Rust is missing, use the official installer:

curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

Then reopen Terminal, or load the environment into this existing shell and verify again:

source "$HOME/.cargo/env"
rustc --version
cargo --version
rustup show active-toolchain

A version line proves the command is found; the next lesson compiles a program to prove the compiler and native linker work together.

01

Locate the tools

Run command -v rustc and command -v cargo. What do the returned paths tell you?

Need a hint?

The shell searches PATH directories in order.

Worked solution

Run the two commands and compare the results. A normal rustup setup resolves commands under your user’s .cargo/bin. The path explains which installed program receives your command; it does not describe the current game folder. If another installation appears first, record it and investigate before changing PATH.

How to verify your result

A screenshot or copied output shows both resolved command paths.

02

Prove a fresh terminal works

Close Terminal, open it again, and repeat the version checks without source.

Need a hint?

The installer normally updates shell startup configuration.

Worked solution

A fresh shell should find the commands automatically. If it does not, activate the current shell with source "$HOME/.cargo/env", confirm that works, then inspect the startup file appropriate to your shell rather than repeatedly reinstalling Rust. The distinction is installed files versus shell command lookup.

How to verify your result

The fresh terminal finds Rust, or you can name the remaining PATH issue precisely.

03

Explain the chain for your episode

Without reading, explain what rustup, Cargo, rustc and the linker contribute.

Need a hint?

Installation, orchestration, compilation, and final executable assembly are separate jobs.

Worked solution

A concise explanation is: rustup manages toolchains; Cargo coordinates package builds; rustc compiles Rust; the native linker combines compiled pieces and system libraries into a runnable executable. We installed the tools needed for that chain, but have not yet built our game.

How to verify your result

The explanation distinguishes all four roles instead of calling them all the compiler.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

zsh: command not found: cargo

What is happening: The command directory may not be on PATH in this shell.

Try this: Open a fresh terminal; if needed source "$HOME/.cargo/env" and inspect command -v cargo.

xcode-select: error or linker cc not found

What is happening: Apple native developer tools are unavailable or not selected.

Try this: Complete xcode-select --install, then retry compilation in lesson 2. Preserve the actual error if installation is already complete.

A version differs from the video

What is happening: Stable Rust advances; the exact printed version is not the lesson’s target.

Try this: Check that the stable toolchain is active and continue unless a dependency documents a specific minimum.

Explain it without the example

Which tool manages installed Rust toolchains, and which compiles Rust source?

Reasoning to compare

rustup manages toolchains. rustc is the compiler. Cargo uses the toolchain to build packages; the terminal is where you invoke these tools.
