Blend biomes and place stable strata

Biome borders have no chunk seams. Starting terrain largely remains still under the rest test.

Previously: Generate repeatable hills from a seed. Keep that working result available before starting this lesson.

Why we need this now

A height function draws a hill, but the simulation decides whether that hill can stand. Putting loose soil on every steep face creates a world that collapses as soon as it enters view. Biomes and strata must therefore generate material arrangements compatible with the rules we already taught.

Your result: Biome borders have no chunk seams. Starting terrain largely remains still under the rest test.

01Choose context before material layers

A slowly varying biome field chooses plains, mountain, sea or beach context per world column. It should form broad regions rather than alternate every few cells. Base height and biome may use separate keyed noise inputs so changing a biome decision does not accidentally scramble the entire height sequence. Blend parameters where appropriate, but material identity remains discrete: a transition band can choose a coherent boundary rather than invent an unsupported half-sand half-stone substance.

02Compute slope from neighbouring heights

For each column, inspect a bounded neighbourhood of settled surface heights. Compare steepness with the material’s approved repose constraint. A low-slope plains column can carry soil, while a steep mountain face exposes stone. Use the same inequality convention as the powder-rest rule, including equality. If generation permits a slope that motion considers unstable, every newly active chunk will rearrange. The lab below makes this consistency decision explicit with a simple maximum height-step threshold.

03Place strata in a defined order

The current design uses soil over stone, with sand at beaches/dunes. Depth can vary deterministically with a low-amplitude field. Water placement and later features must respect the base solid geometry; unsupported boulders, caves immediately below the sea or dry soil under generated water can break the rest guarantee even when slopes look correct. Build generation as ordered functions with explicit inputs and inspect a cross-section before adding every feature. Material colours should communicate strata without speckled per-cell noise.

04Verify rest before polishing biomes

Generate a sample set spanning all v1 biomes and run 600 ordinary simulation ticks. The milestone allows fewer than 0.1 percent of cells to move in the rest fixture. Count actual moved cells or an agreed displacement metric, not only final-state difference, because a grain could move and later return. Use the same generator version and environment inputs for reproducibility. If the scene is unstable, fix generation or reconcile the movement constraints before hiding it under atmospheric art.

#[derive(Debug,PartialEq)]
enum Surface { Soil, Stone }
fn surface_for_slope(left:i32, here:i32, right:i32, max_step:i32)->Surface {
    let steep=(i64::from(here)-i64::from(left)).abs()
        .max((i64::from(right)-i64::from(here)).abs());
    if steep>i64::from(max_step) { Surface::Stone } else { Surface::Soil }
}
#[test]
fn loose_surface_obeys_the_declared_rest_limit() {
    assert_eq!(surface_for_slope(10,11,12,1),Surface::Soil);
    assert_eq!(surface_for_slope(10,13,14,1),Surface::Stone);
    assert_eq!(surface_for_slope(10,10,10,1),Surface::Soil);
}

01

Check equality

Does slope exactly equal to max_step expose stone here?

Need a hint?

Read the strict greater-than comparison.

Worked solution

No. Equality is allowed as Soil. Match this choice to the movement rule; if the powder rule slides at equality, reconcile one of the conditions before generation claims rest.

How to verify your result

Generation and movement agree on the threshold case.

02

Test a biome seam

Why generate neighbouring chunks in different orders at a plains/mountain border?

Need a hint?

The boundary depends on world coordinates, not loading order.

Worked solution

Both orders must choose the same biome and material layers for each column. A chunk-local RNG or missing neighbour query often reveals itself at such a seam.

How to verify your result

Material borders match across independent chunk generation.

03

Count movement

Why can final-state equality underestimate rest-test movement?

Need a hint?

Material can move and return.

Worked solution

Track committed move events or the agreed per-cell moved marker across the run. A final hash only shows the final arrangement and may miss oscillation or temporary collapse.

How to verify your result

The rest metric measures actual activity over 600 ticks.

When it goes wrong

Start with the observed symptom. Change one assumption at a time instead of pasting fixes until the error disappears.

New hills collapse when viewed

What is happening: Loose surface slopes violate movement stability.

Try this: Generate stone where the approved repose limit is exceeded.

Biomes become speckled noise

What is happening: Biome variation changes at cell scale.

Try this: Use broad regions and coherent boundary decisions.

Rest test passes a visibly jittering pond

What is happening: It compares only initial/final state.

Try this: Measure moves over time and inspect water/soil initialization.

Explain it without the example

Why can't arbitrary steep hills simply receive a sand surface layer?

Reasoning to compare

Sand obeys its repose rule and would slide immediately. Generation must produce a state compatible with the simulation's resting rules.
